## 0. 怎么用这份序列（先读）



1. **一次只发一条 prompt，做完验证通过再发下一条。** 不要让 AI 一次性把整个系统写完 —— 帧格式、阈值都还没实测，一次写大了必然返工。

2. **真人负责硬件，AI 负责代码。** 装软件、接线、采样、压测、录视频只能人来做；AI 写脚本、配置、测试和分析工具。

3. **Gate 不过不前进。** 每条任务的 "验证" 就是一道小门；没过就按 "不过怎么办" 处理，不要跳。

4. **先离线、后实时。** 拿到板子和手册之前，先让 AI 用模拟 / 回放数据把判定算法、MQTT、HA 链路写通；硬件一到只换 "数据来源"，后面不动。

5. **所有阈值写进配置文件，先给占位值，S1 实测后再填。** 不要让 AI 把阈值硬编码在代码里。

6. 全本地：不接云、不写后端、不训 ML、不做原生 App（这些是 MVP 明确不做的）。

### A2・数据读取抽象层（模拟 / 回放模式）



| 项  | 内容                                          |
| -- | ------------------------------------------- |
| 目标 | 定义统一的 "一帧" 中间结构，让后面的判定算法不依赖真实导出格式           |
| 前置 | A1 完成                                       |
| 产出 | `src/data_source/` 下的帧结构定义 + 模拟数据源；真实适配器留接口 |
| 验证 | 模拟源能逐帧吐出统一结构，打印字段正常                         |

**为什么先做这个：** 真实导出 / 串口格式要第 1 天找老师要手册才知道。先用一个统一结构把链路写通，格式拿到后只补一个 "翻译适配器"，判定和 MQTT 都不用改。

**发给 AI 的 prompt：**



```
在 src/data_source/ 里实现数据读取抽象层：

1. 定义统一帧结构 Frame（用 dataclass），字段先包含：
   - timestamp: float
   - range_energy: list[float]   # 1DFFT 各距离门能量（长度=距离门数）
   - targets: list[dict]         # 授权软件给的目标信息（距离/角度/速度/状态），没有就空列表
   - raw: dict                   # 预留，存原始导出字段
2. 定义抽象基类 DataSource（iter_frames() 生成 Frame），再实现一个 SimulatedSource：
   - 可配置生成"空房 / 走动 / 静坐"三种合成场景的帧序列（能量曲线自己造得像就行），
     用于在没有硬件时测试判定逻辑；
3. 留一个空的 FileReplaySource 接口（读导出文件）和 SerialSource 接口（实时串口），
   只写注释说明"等拿到手册/导出格式后实现"，不要现在编格式。
4. main.py 里加一个 --source simulated 模式，能循环打印每帧的 range_energy 概要和 targets。
```

**不过怎么办：** 字段不够没关系，等 B1 看到真实导出格式再让 AI 给 Frame 加字段。

### A3・存在判定核心纯逻辑 + 单元测试



| 项  | 内容                                     |
| -- | -------------------------------------- |
| 目标 | 把 "人在 / 离开" 判定写成不碰串口、不碰网络的纯函数，先用合成样本测对 |
| 前置 | A2 完成                                  |
| 产出 | `src/detector/` 判定模块 + `tests/` 单测     |
| 验证 | 单测覆盖：走动→有人、离开→无人、去抖不误翻、静坐保持有人（v2 后）    |

**发给 AI 的 prompt（先只做运动检测 + 去抖，静坐下一步再加）：**



```
在 src/detector/ 实现存在判定，保持纯函数、可单测，不读串口不发网络：

1. 运动检测：一帧内"超过底噪的距离门能量之和"（或超过阈值的门数）大于 energy_threshold → 该帧为"有人候选"；
2. 去抖：连续 debounce_frames_enter 帧有人候选才把 presence 翻成 1；
   连续 debounce_frames_leave 帧无人候选才翻回 0；进/出去抖帧数分开配，避免状态来回抖；
3. people_count：优先取 Frame.targets 的个数（授权软件目标信息），夹在 0/1/2；
   目标数拿不到时先返回 None 并在注释标 TODO，不要硬猜；
4. 维护一个 Detector 类，update(frame) -> {presence, people_count, changed}，
   changed 表示这一帧状态发生翻转（供后面发日志/MQTT）；
5. 在 tests/ 写单测：构造合成帧序列验证 走动→1、离开→0、帧数不够时不翻转。
阈值全部从 config 读。先不要写静坐判定，接口里留 still 相关占位即可。
```

**做完验证：** 跑单测全绿；再用 A2 的 SimulatedSource 在 `--source simulated` 下看 presence 随场景正确翻转。

**A3b・叠加静坐判定（单测通过后再发）：**



```
在现有 Detector 上叠加静坐判定（v2），仍然纯函数、可单测：
- 静坐条件：最近一段时间窗口内 range_energy 整体方差小于 still_energy_variance（能量稳定），
  且有某个距离门持续高于底噪达到 still_persist_frames 帧（距离门持续占用）→ 判定为"有人（静坐）"；
- 静坐状态与运动状态合并出最终 presence，静坐期间不得翻成 0；
- 新增的窗口长度、阈值全部进 config；补对应单测：静坐 10 分钟量级的合成序列不误判为空房。
```

**不过怎么办：** 单测不过就让 AI 修；静坐合成逻辑造不像没关系，B1 用真实样本校准。

**分三步发 prompt（递进，别一次要）：**




**不过怎么办：** 帧错位就让 AI 按手册核对包头 / 字节序 / 校验；切换正确率不够就回到 B1 重新调阈值，不要硬进 B3。
