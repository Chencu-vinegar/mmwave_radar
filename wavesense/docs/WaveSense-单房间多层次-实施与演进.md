# WaveSense 单房间多层次：实施流程与演进路线

> 一份综合文档：从 DEV202/DEV113P 开发板的原始信号 → 最小功能 MVP 落地 → 单房间内"多层次"空间感知演进。
> 本文档整合《WaveSense-最小功能实施流程.md》与《WaveSense-MVP与最终功能.md》的内容，作为项目执行与答辩的主文档。

---

## 1. 项目定位

**一句话**：用实验室发放的矽典微 DEV202 / DEV113P 毫米波开发板（单房间 · 单雷达），实现"人在 / 位置 / 灯控 / 进出记录"全自动、数据完全不出局域网的演示系统；并在 MVP 基础上演进为**单房间内多层次空间感知**——不扩多房间，而是把一个房间按距离 / 角度切成多个区域，每个区域接不同联动。

**数据链路**：开发板 → 串口模组连电脑 → 授权软件（波形 / 1DFFT / 2DFFT，导出 / 回放）→ Python 存在判定 → MQTT → Home Assistant。

**数据通路澄清**：不存在"把原始数据转换为 XenP 成品数据"的步骤——XenP 轨迹帧是 ICL1122 固件在模块内部算好的输出格式；DEV202 用同一颗 ICL1122，板内已内置 DSP / 滤波 / CFAR，授权软件直接输出处理后的成品数据（1DFFT / 2DFFT / 目标信息），可直接导出用于分析。

## 2. 目标界定：MVP 与最终功能

**MVP（2–3 周必达，单房间）**：
1. 人在 / 离开检测（阈值 + 去抖，含静坐）；人数 0 / 1 / 2；
2. 灯控联动：进入立即亮灯、离开延时 5 分钟关灯；
3. 进出事件记录（Logbook + 本地 SQLite）；
4. 本地网页仪表盘（人数 / 灯状态）。

**最终功能（单房间多层次，非多房间）**：区域级存在（目标距离 / 角度 → 区域归属：门口 / 书桌 / 休息区）+ 行为状态（活动 / 静止）+ 区域差异化联动（台灯 / 主灯 / 夜灯）+ 场景切换（进门 → 学习 → 休息 → 夜间起床）+ 房间平面仪表盘。

**层次结构**：空间区域层（人在哪个区）× 行为状态层（活动还是静止）× 场景响应层（该区域怎么联动）。

| 维度 | MVP | 最终功能（单房间多层次） |
|---|---|---|
| 感知 | 人在 / 离开 + 人数 0/1/2 | 区域级存在 + 行为状态 + 区域转移；多人分区计数 |
| 联动 | 灯控（来即开、离开延时关） | 区域差异化联动（书桌台灯 / 床区夜灯 / 门口进出判定）+ 场景切换 |
| 界面 | HA 本地仪表盘 | 房间平面示意图 + 目标实时位置 + 区域状态面板 |
| 数据 | presence 0/1 + 进出日志 | 区域事件日志（何时在何区域）+ 作息洞察 + 原始信号训 ML（可选） |
| 算法 | 阈值 + 去抖（规则） | 目标距离 / 角度 → 区域归属；区域状态判定（规则或 ML） |
| 部署 | 单机（采集电脑 + 旧笔记本 Docker） | 单雷达能力最大化：同一链路升级判定与联动 |
| 验收 | 5 项指标 | 产品级：误报率、区域判定准确率、场景切换鲁棒性、断电自恢复 |

**验收指标（MVP 5 项）**：空房 1 h 误报 = 0 ｜ 静坐 30 min 持续判定"有人" ｜ 双人判定计数 = 2 ｜ 灯控端到端 < 1 s ｜ 进出日志误差 < 2 s。

## 3. 核心原则（3 条）

1. **从最简算法开始**：存在判定用"阈值 + 去抖"，不先写复杂模型；
2. **每阶段有验证门（Gate）**：未通过当前 Gate 不进入下一阶段；
3. **日志 / 仪表盘最后做**：判定方案可能因数据特征调整，先做 UI 会反复返工。

## 4. Phase 1 · MVP 详细实施流程（从原始信号到最小功能）

**5 阶段 · 14 子步骤 · 5 道验证门**，总工期约 1 周打通主链路 + W2–W3 测试验收。

### S0 环境搭建与数据打通（D1 上午）｜ 产出：实时数据可读

| # | 子步骤 | 具体动作 | 完成标准 |
|---|---|---|---|
| 0.1 | 安装软件 | 找实验室要授权软件安装包 + 2 份授权码，装到采集电脑 | 工具能打开、授权正常 |
| 0.2 | 连接硬件 | 装串口模组驱动；USB 连接 DEV202、DEV113P；供电 | 系统识别 2 个串口设备 |
| 0.3 | 参数摸底 | 记录两块板各自的帧速、距离门数、底噪、探测范围 | 参数记录表（用于阈值设计） |
| 0.4 | 数据可见性验证 | 空房 vs 挥手，观察波形 / 热图变化 | **Gate 1：有明显差异** |

### S1 数据理解与采样（D1 下午）｜ 产出：三类样本 + 特征结论

| # | 子步骤 | 具体动作 | 完成标准 |
|---|---|---|---|
| 1.1 | 确认可用数据层 | 弄清授权软件能直接看到 / 导出哪些数据：波形、1DFFT（距离谱）、2DFFT（速度谱）、目标信息 | 数据导出格式文档 |
| 1.2 | 三类采样 | 采集并保存 ≥5 min：**空房 / 有人静坐 / 有人走动**，标注场景与时间 | 每类 ≥1 份带标签数据文件 |
| 1.3 | 特征对比 | 对比三类数据的距离门能量、目标信息差异；确定判定特征（如"距离门能量和 > 阈值 = 有人"） | 特征选择结论 |
| 1.4 | 可分性验证 | 用样本验证静坐 vs 空房能否区分 | **⚠️ Gate 2（成败关键）**：可分则继续；不可分则降级"运动存在检测" |

### S2 存在判定脚本（D2）｜ 产出：presence.py

| # | 子步骤 | 具体动作 | 完成标准 |
|---|---|---|---|

| 2.4 | 脚本 v2 | 叠加静坐判定：能量稳定 + 距离门持续占用 | 静坐 10 min 不误判为空房 |

## 5. Phase 2–3 · 从 MVP 演进到单房间多层次

### 演进路径（每项 MVP 能力 → 最终形态）

| MVP 能力 | 最终功能形态 | 需要的增量 |
|---|---|---|
| 人在 / 离开（阈值判定） | 区域级存在：目标落在哪个区域、活动还是静止 | 目标距离 / 角度 → 区域归属 + 状态判定 |
| 单房间单雷达 | 房间分区感知：门口 / 书桌 / 休息区 Zone Map | 按距离门（~70.6 cm 分辨率）与角度划分区域 |
| 人数计数（0 / 1 / 2） | 多人分区计数（两人各在哪个区域） | 目标跟踪 + 区域关联 |
| 灯控自动化 | 区域差异化联动：书桌区台灯、床区夜灯、门口判定进出 | HA 场景自动化（基于区域状态） |
| 本地仪表盘 | 房间平面图 + 实时目标位置 + 区域状态 | 位置数据可视化 |
| 进出日志 | 区域事件日志 + 作息洞察（何时在何区域） | 区域级事件记录 + 长期数据积累 |

### 单房间多层次实现原理

- **Zone Map**（房间横切面 0–5.6 m，距离门 ~70.6 cm）：门口区（0–1.5 m，进出判定）｜ 书桌区（1.5–3 m，学习 / 久坐）｜ 休息区（3–5.6 m，床 / 睡眠）。DEV202 置于门口一侧，波束覆盖全房间。
- **判定链路**：目标距离 + 角度 → 区域归属 → 区域状态（活动：能量波动；静止：能量稳定 + 距离门持续占用）→ 触发该区域联动与场景。
- **区域差异化联动示例**：进门（门口区活动）→ 主灯亮 ｜ 书桌区静坐 → 台灯亮 + 主灯调亮 ｜ 休息区静止 + 熄灯 → 主灯关 + 夜灯模式 ｜ 夜间书桌 → 休息区转移 → 自动切睡眠场景。

### 阶段安排

- **Phase 2（MVP 后）＝ 空间感知升级**：划分 Zone Map → 目标区域归属判定 → 区域差异化联动（台灯 / 夜灯 / 主灯）。
- **Phase 3（长期）＝ 场景自动化与界面**：基于区域转移的场景切换（进门 → 学习 → 休息 → 夜间起床）+ 房间平面仪表盘 + 可选行为分类 ML。
- **明确不做**：多房间扩展、原生 App / 云远程（可选 Phase 3 之后）、家属推送告警（可选）。

## 6. 关键验证点：Gate 2（静坐 vs 空房）

- **位置**：S1（第 1 天下午），是整个 MVP 是否成立的判定点。
- **做法**：用授权工具分别保存"空房"与"有人静坐看书"各 ≥5 分钟数据，对比 1DFFT / 2DFFT 差异（能量、目标信息）。
- **结果分支**：可分 → 按完整方案继续（含静坐检测）；不可分 → 降级为"运动存在检测"（灯控 / 日志仍可演示），答辩 PPT 主动说明取舍。

## 7. 注意事项（3 个坑）

1. **S1 不要跳过**：静坐场景是相对 PIR 的核心卖点，也是开发板方案最大的不确定性，务必第 1 天实测；
2. **判定分层递进**：先让"走动→有人、离开→无人"跑通，再叠加"静坐能量稳定→有人"；区域化演进同样先单区域跑通再切多区域；
3. **联动依赖判定稳定**：灯控、日志、仪表盘全部依赖 presence 质量，判定未达标前不做 UI 和自动化调优。
