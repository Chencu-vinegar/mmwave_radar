## B1 离线样本分析（2026-10-22 → 10-29）

1. 对授权软件导出的 DAT 做二进制格式逆向：
   `ICLH`(4B) + 长度 LE(2B) + 类型(1B) + 通道(1B) + 数据段 + `ICLT`(4B)；
   芯片头大端 u32（0xAA 开头）；8 复门 int16 交织 I/Q；一雷达帧 = 64 chirp × 2 通道。
2. 首批样本统计：走动与空房在平均能量口径下未分离，判断采样条件不一致，产出重采协议。
3. 10-29 重采后翻盘：走动 P50=74.24 ≫ 空房 P99=32.34，静坐 P50=19.29 居中。
   写入 config：`energy_threshold=53.0`、`exclude_dc_bin0=true`。
4. 用真实解码帧回测 Detector：empty 0% presence、walk 99%、sit 0%（静坐路径待标定）。

## B2 实时链路（2026-11-03 ~ 11-05）

### 第 1 步：FileReplaySource 回放链路
- 抽出 `dat_parser.py`（解析器），`FileReplaySource` 自动用 empty 样本扣底噪；
- 实测：empty→presence=0，walk→第 3 帧翻 1 保持。

### 第 2 步：SerialSource 实时串口（排障过程是重点）
- 初版按 DAT 的 ICLH 包装层拼帧，实机"没反应"。
- 用 `tools/serial_probe.py` 抓原始字节对拍：
  - 921600 收到 ~200KB/5s，**ICLH/ICLT 出现 0 次**，`AA..09` 芯片头 5018 个。
  - 结论：ICLH/ICLT 是授权软件导出 DAT 时加的外壳，板子裸串口发的是**定长 40 字节芯片帧**
    （AA 头 4B + 8 门 I/Q int16 32B + 尾 4B），128 个芯片帧 = 1 雷达帧。
- 重写 SerialSource：找到第一个 AA 头后按 40B 定长切，失步自动重扫；
  用录制的 serial_capture.bin 离线验证：拼出 39 个雷达帧、resync 仅开头对齐。
- 实机：20 帧/2 秒、resync 稳定，门能量正常。

### 第 3 步：serial 接 Detector + 实机底噪学习
- 空房误报：实机环境与录样本时不同，旧底噪扣不准。
- 新增 `--learn-bg 30`：空房状态下实测每门 dB 底噪，写回 config 的 `live_bg_db`。
- 学习后空房残差能量 ≈ 0、presence 稳定为 0。
