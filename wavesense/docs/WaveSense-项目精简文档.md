## 第一部分 · 项目申请书（Proposal）精简版

**一句话**：用实验室发放的矽典微 DEV202/DEV113P 毫米波开发板，做出「人在 / 位置 / 灯控 / 进出记录」全自动、数据完全不出局域网的可演示系统。

### 背景痛点
- PIR（¥59）检测不到静坐的人；摄像头隐私侵入感强；
- 成品毫米波传感器要么上云（小米 ¥99 促，生态封闭）、要么贵（Aqara FP2 ≈¥600，需网关）；
- 24 GHz 雷达不拍脸、不收音、不怕暗光遮挡，是「存在感知」的正确方向。

### 目标（4 项）
1. 存在 / 人数 / 位置检测（**含静坐**，与 PIR 的核心差异）；
2. 人来灯亮、离开延时关灯；
3. 本地进出记录，网页可回看；
4. 全本地运行，断外网照常工作。

### 技术方案
- **链路**：DEV202（1T2R，ICL1122）+ DEV113P（2T4R）开发板 → 串口模组连电脑 → 矽典微授权软件（波形 / 1DFFT / 2DFFT、数据导出 / 回放）→ Python 存在判定 → MQTT（本地 Mosquitto）→ Home Assistant（仪表盘 + SQLite 日志 + Logbook）；
- **不做 ML**：开发板可获取原始数据、理论可行，但 2–3 周时间紧；MVP 用「简单信号特征 + 规则引擎」做存在判定，真·ML 列为 Future Work 或加分项；
- **灯控**：优先 WiFi 智能灯泡（避免 220V 强电），5V 继电器作硬件联动备份演示。

### 方案对比
| 方案 | 静坐检测 | 数据上云 | 二次开发 | 差异 |
|---|---|---|---|---|
| PIR ¥59 | ❌ | 通常需网关/云 | 低 | 本项目能检测静坐 |
| 小米 ¥99（促） | ✅ | 依赖米家云 | 封闭生态 | 本项目全本地、开放 |
| Aqara FP2 ≈¥600 | ✅ | 需 Aqara 云/网关 | 门槛高 | 本项目 BOM 仅 ¥60–130 |
| **WaveSense** | ✅（自研判定，待实测） | **全本地、断外网可用** | Python + HA + 矽典微授权工具 | 教学/极客开源方案 |

> 诚实定位：小米/Aqara 在工业设计、续航、App 体验上完胜；本项目定位为「可本地部署、可二次开发的教学/极客演示方案」，不主张量产替代。

### 里程碑（2–3 周）
| 周次 | 目标 | 关键任务 |
|---|---|---|
| W1 | 打通主链路 | 装授权软件并连通 DEV202/DEV113P（串口模组）；用工具验证波形/热图与安装位置；写 Python 数据读取与存在判定脚本；接 MQTT + HA；实现人来灯亮、离开延时关灯 |
| W2 | 补全功能 | 温暖居家风仪表盘（人数 + 位置散点 + 灯状态）；Logbook 进出记录；加「长时间不动 / 疑似跌倒」本地规则事件 |
| W3 | 演示与答辩 | 边界测试（空房误报 / 静坐 / 双人计数）；录 3–5 段演示视频；做 PPT；留 1 天缓冲 |

### 预算
- 开发板 / 串口模组 / 授权软件 **¥0**（实验室统一发放：每组 2 块开发板 + 2 个串口模组 + 2 份授权软件）；
- 额外约 **¥60–130**：5V 电源 + 杜邦线（¥10–20）、WiFi 智能灯泡（¥30–80）、5V 光耦继电器可选（¥10–20）；
- 旧笔记本 Docker 跑 HA，不另购树莓派。
- （价格为 2026-10-18 参考价，采购前以实时页面为准）

### 隐私与伦理
- 雷达输出的是信号/目标数据（波形、距离谱或目标信息），**不含人脸、语音、身份信息**，分析后仅保留「人在/离开」状态；
- 数据全本地存储（SQLite），不接云、不做公网穿透；
- 疑似跌倒等异常事件 MVP 阶段**仅本地记录，不自动外发**。

### 主要风险与应对
| 风险 | 应对 |
|---|---|
| 工具/数据读取不熟 | 第 1 天装好授权软件并连通开发板，先用工具自带波形/热图确认数据正常 |
| 窗帘/风扇误报 | 调雷达灵敏度与安装角度；空房 1 小时压测；误报写进答辩材料主动说明 |
| 2–3 周时间紧 | 严格砍掉 ML、原生 App、云远程；只做主链路；留 1 天缓冲 |
| 自研存在判定不达预期 | D2 用授权工具实测原始数据；不达标降级为「运动存在检测」并在 PPT 说明取舍 |
| 串口/USB 连接不稳定 | 检查串口模组驱动与供电；缓冲日处理 |

### 验收标准（演示验收）
- 空房间连续 1 小时误报 = 0 次；
- 人静坐看书 30 分钟仍被持续检测到；
- 两人同时在房，自研判定脚本稳定计数为 2；
- 人进入到灯亮的端到端延迟 < 1 秒；
- 进出日志时间戳与实际动作误差 < 2 秒。

### 交付物
可现场演示系统（雷达 + Python 脚本 + HA 仪表盘 + 灯联动 + 进出日志）｜ 3–5 段演示视频 ｜ 答辩 PPT ｜ 配套文档（申请书、PRD、技术设计文档）。

## 第二部分 · 产品需求（PRD MVP）精简版

**定位**：不接云、不拍脸，用毫米波雷达看清谁在房间里——灯自己亮，进出有记录。2–3 周交付可演示课程 MVP，邀请 5–10 人试用。

### 目标用户
便利型住户，课程演示覆盖两类场景：
- **独居老人**（如张阿姨，65 岁）：起夜灯灭摸黑不安全；长时间不动无人知晓；
- **忙碌白领**（如小李，28 岁）：出门忘关灯；想知道白天有没有人进过家。

### 现有方案为何不行
PIR 检测不到静止的人；小米依赖米家云、不可二次开发；Aqara 硬件贵、本地化需加 Zigbee 网关；自写后端 2–3 周做不完。→ WaveSense：全本地 + 开放 + BOM ¥60–130。

### MVP 核心功能（P0，4 项，缺一不可）
| # | 功能 | 验收要点 |
|---|---|---|
| 1 | 人在 / 位置检测（自研判定） | 授权工具 + 串口模组连续采集 10 min 稳定；单/双人判定稳定；静坐 30 min 持续判定「有人」 |
| 2 | 灯联动自动化 | 进入 1 s 内亮灯；离开 5 min（可配置）灭灯；静坐期间灯不灭 |
| 3 | 进出事件记录（Logbook + SQLite） | 每次 0↔N 切换生成带时间戳事件；误差 < 2 s；断外网可回看 |
| 4 | 本地网页仪表盘（温暖居家风） | 手机 + 电脑可开；一屏看完人数/位置/灯/记录；位置散点实时更新 |

### Nice to Have
- 规则引擎异常标记：`long_still`（静坐超 30 min）/ `possible_fall`（高度骤降 + 速度≈0 持续 10 s），**仅本地记录，不外发**；
- 5V 继电器直控台灯，作为硬件联动答辩备份。

### 明确不做（Out of Scope）
从零训练 ML（开发板数据可获得，但课程时间不强制）｜ 原生手机 App ｜ 任何云服务 / 公网远程查看 ｜ 家属推送告警 ｜ 多房间扩展。理由：2–3 周硬约束，聚焦「开发板→授权工具→判定→HA→灯→日志」一条端到端链路。

### 成功指标（与 Proposal 验收一致）
空房 1h 误报 0 ｜ 静坐 30 min 持续检测 ｜ 双人计数 = 2 ｜ 灯控端到端延迟 < 1 s ｜ 日志时间戳误差 < 2 s。

### 设计基调（Look & Feel）
温暖居家风：浅色背景 + 大圆角卡片 + 大字体；状态色块——绿=有人、灰=无人、暖黄=灯开；一屏看完不钻二级菜单；状态不只靠颜色区分（WCAG 2.1 AA 目标）。

### 技术要点
全本地运行，不暴露公网 ｜ 开发板→串口模组→授权软件（读数据/导出）→Python 存在判定→MQTT→HA ｜ 灯控优先 WiFi 智能灯泡 ｜ 采集断线时仪表盘提示「雷达离线」不崩溃 ｜ 断电重启后自动恢复。

### 预算与时间线
- BOM ¥60–130（旧笔记本跑 HA）或 ¥450–650（含树莓派 4B 2GB）；雷达 ¥0（学校）；月运营 ¥0；
- 时间线：2–3 周（约 15 个工作日 + 1 天缓冲）；W1 主链路 → W2 仪表盘/日志/异常规则 → W3 打磨演示。

### DoD（MVP 可交付判定）
- 4 个 P0 功能端到端跑通（存在检测 / 灯联动 / Logbook / 仪表盘）；
- 串口断线时仪表盘提示「雷达离线」，不崩溃；
- 手机 + 电脑浏览器均可正常打开 HA 仪表盘；
- 完整用户旅程走通：进门 → 灯亮 + 位置出现 → Logbook 记录 → 离开 → 5 分钟后灯灭；
- 5 项成功指标全部达标；5–10 位朋友/同学完成试用；
- 部署路径可用：旧笔记本 Docker / 树莓派开机自启，断电重启自动恢复。
